To plan and apply a schema change you need one repository: `ptah`, which holds
the engine and the CLIs. The other public repositories install it, run it for
you on Kubernetes, add an engine it does not build in, or check it. Use the map
to find the ones your work needs, and leave the rest out.

## Choose a path

Each path below is complete on its own, and the first one needs no other
component. Start with the first unless your databases are managed from
Kubernetes.

<EcosystemText view="paths" />

Providers are a separate choice, and they apply on any path. A provider is needed
only for an engine Ptah does not build in. [Supported databases](../../databases/overview/)
lists what Ptah builds in, and [executable providers](../../extend/executable-providers/)
explains how a provider is installed and selected.

## Releases and compatibility

Ptah, the operator, the console and the providers have separate releases, and a
new version of one does not imply a matching version of another. Each project
publishes its own compatibility statement, so this page lists no version numbers:

- **Ptah** publishes [its releases](https://github.com/stokaro/ptah/releases), and
  the [support matrix](../../databases/support-matrix/) lists the database release
  lines it covers.
- **The operator** runs a Ptah release image in its Jobs and publishes
  [which Ptah build each operator release runs](https://operator.ptah.run/support/ptah/).
- **The console** is built against one operator release and publishes
  [which console release goes with which operator release](https://github.com/stokaro/ptah-console/blob/master/docs/compatibility.md).
- **A provider** declares the provider contract it needs, and
  [executable providers](../../extend/executable-providers/#install-an-official-provider)
  explains how Ptah picks a release it can run.
- **Atlas compatibility** is measured in `ptah-atlas-conformance`, and
  [conformance](../../atlas/conformance/) reports what those runs show.
