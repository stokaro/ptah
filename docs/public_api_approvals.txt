# Describing what a PostgreSQL extension provides needs a list, and a struct
# with a slice field is no longer comparable. Extension and DBExtension gained
# Provides []string so the compatibility surface can answer "does this document
# still depend on something this extension supplies" -- the question that
# matters, and one the extension's own name does not answer: `isn` supplies the
# type `isbn`. Reading the name instead shipped a regression that made Ptah's
# own inspect output unreadable to Ptah.
#
# The cost is comparability: consumers can no longer use == on these structs or
# use them as map keys. Nothing else changed -- no symbol was removed and no
# existing field altered.

# A PostgreSQL RLS policy name is scoped to its table, not to the schema:
# CREATE POLICY tenant_isolation succeeds once on each of two tables in one
# schema and is refused only when repeated on the same table. SchemaDiff
# reported additions as bare names, so a caller could not tell which of two
# identically named policies was missing and neither could the planner -- it
# resolved the name against the desired schema and emitted the wrong table's
# policy. RLSPoliciesAdded therefore becomes []RLSPolicyRef, the shape
# RLSPoliciesRemoved and TriggersAdded already have.
#
# The cost is that consumers reading rls_policies_added get objects with
# policy_name and table_name instead of strings. Nothing was removed and no
# other field changed.
v0.2.0 go.5x5.cz/ptah/migration/schemadiff/types

# SQL Server synonyms become a schema object kind, which widens ast.Visitor with
# VisitCreateSynonym and VisitDropSynonym (stokaro/ptah#1030). Every node kind
# this interface has ever gained has been an incompatible change by the same
# mechanism, and the alternative -- a second visitor interface, or an optional
# type assertion -- would let a renderer silently ignore a node instead of
# failing to compile. That compile failure is the property the interface is for:
# it is what guarantees that a new object kind is answered by every dialect
# rather than dropped by the ones nobody remembered to edit.
#
# core/renderer is listed for the same change: RenderVisitor embeds ast.Visitor,
# so widening one widens the other.
v0.2.0 go.5x5.cz/ptah/core/ast
v0.2.0 go.5x5.cz/ptah/core/renderer

# migration/importer.Parser gained NamePattern and its Parse now returns a
# *ParseResult instead of a []SourceMigration (stokaro/ptah#2231).
#
# The interface is what makes the accounting total. Every one of the five
# parsers carried the same three lines that dropped an unrecognized file with
# `continue // ignore non-migration files`, so a migration one directory down or
# a name off by one character left no trace -- and ptah.sum was then written
# over the subset that survived, so the truncated directory validated clean.
#
# The compile failure is the property the signature change is for: a parser that
# does not report what it consumed cannot be registered, and the walk in
# AccountForSource then declines everything it did not hear about. An additive
# optional method would have let a parser keep silently dropping files, which is
# the defect itself.
v0.2.0 go.5x5.cz/ptah/migration/importer
