# CREATE POLICY tenant_isolation succeeds once on each of two tables in one
# schema and is refused only when repeated on the same table. SchemaDiff
# reported additions as bare names, so a caller could not tell which of two

# resolved the name against the desired schema and emitted the wrong table's
# policy. RLSPoliciesAdded therefore becomes []RLSPolicyRef, the shape
# RLSPoliciesRemoved and TriggersAdded already have.

# The planner stops taking the declaration, and an index addition carries the
# index it creates.
#
# `Planner.GenerateMigrationAST` took the desired schema beside the diff, and
# every dialect planner reached back into it for facts the diff did not carry.
# Those facts travel on the diff now, so the parameter is gone: a planner
# renders what the diff describes and nothing else. That is stokaro/ptah#2315's
# measure of done.
#
# `SchemaDiff.IndexesAdded` was the last category that named its operand instead
# of carrying it -- a name and a table, with the definition left in the
# declaration for a planner to look up. Looking it up is what needed the whole
# document to render one CREATE INDEX. `IndexChanges` carries the declaration
# and the relation it belongs to; `IndexAdditions()` still answers the
# references every caller that only needs identity was written against, and the
# JSON is unchanged -- `indexes_added` has always been an array of references.
#
# The constraint lists are the same retirement one family further. `SchemaDiff`
# carried a NAME list and a record list per direction -- `ConstraintsAdded`
# beside `ConstraintsAddedWithTables` -- explicitly not index-aligned, so every
# consumer correlated them by name and a name with no record was a shape a
# planner had to go looking in the declaration for. One list per direction
# carries the records; `Names()` answers the question the name list answered.
#
# `constraints_added` and `constraints_removed` carry the records on the wire
# now, and the `_with_tables` keys are gone. The records is what the pair always
# meant, and the `identity` a consumer is documented to read is on them.

# The six public planning entry points drop the declaration too, and the
# validation it fed moves to the comparison.
#
# `GenerateSchemaDiffAST` and its five siblings kept the parameter after the
# planners stopped reading it, because it fed two validations of the whole
# desired schema: identifier rules that answer questions BETWEEN declarations,
# and the renderer's rules about what a target can host. Neither can run from a
# diff -- a conflict between two unchanged tables is invisible to a change set
# that names neither -- so both moved to where the whole target is supplied.
# `schemadiff.ValidateDesiredSchema` is that one predicate, called by the
# comparison and by the surfaces that reach the comparator through a variant
# returning no error.
#
# Nothing is looser. Every comparison that carries server information makes the
# refusal before it compares, the rollback direction makes it in
# `migration/generator` where the prior schema exists, and render and plan still
# share one validation, which is what stokaro/ptah#1717 asks for.

# ast.Visitor carries one method, VisitNode(Node) error. An embedder that
# implements the interface answers one method instead of a method per node kind,
# and ast.NoopVisitor is gone: a partial consumer writes one type switch, or an
# ast.VisitorFunc.
#

# visitor its own receiver. An embedder that relied on Accept walking a
# StatementList, or on an alter operation handing over its nested column, does
# that walking itself now.
